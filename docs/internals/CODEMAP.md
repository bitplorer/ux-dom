# Code map — `codemap/`

[`codemap/`](codemap/index.json) is a persisted, machine-readable map of
`src/ux_dom`, sharded one file per module. It is generated by
[`scripts/codemap.py`](../../scripts/codemap.py) (stdlib only, AST-based) and
checked in CI. The prose companion is [MODULE_MAP.md](MODULE_MAP.md).

## Rule

**A PR regenerates only the shards its change touches. The codemap diff in
review is the blast radius:** which modules' imports, reverse edges, public
names and consumers moved.

```bash
python scripts/codemap.py --write-changed              # PR authors: rewrite stale shards only
python scripts/codemap.py --check                      # CI: exit 1, naming each stale shard
python scripts/codemap.py                              # rewrite every shard, remove orphans
python scripts/codemap.py --module ux_dom.cli.doctor   # one module's entry (+ loc)
python scripts/codemap.py --module ux_dom/scripts/x_element.js
```

An in-flight PR that goes stale (because `main` moved, or because it touched
`src/`, tests or docs) needs only `python scripts/codemap.py --write-changed`.
Shards of a deleted module are orphans: `--check` names them, and both write
modes delete them.

The output is deterministic (sorted keys and lists, no timestamps or commit
hashes), so a shard changes only when a module's imports, public names or
consumers change. A comment-only edit changes nothing.

## Layout

| File | Content |
|------|---------|
| `index.json` | `layers` (module prefix → layer, longest prefix wins; the root `ux_dom` matches only itself; table lives in the script), `public_api` (names re-exported by `ux_dom/__init__.py` → defining module, following re-exports, star imports and `X = Y` aliases), `cycles_module_level` (SCCs larger than one, module-level imports only), and `modules` / `assets` (name → layer). A module that matches no layer prefix fails the build. |
| `modules/<dotted.name>.json` | `{name: {path, layer, public, imports_internal, imported_by, consumers}}`. There is no `loc`: it changes on every edit and would make concurrent PRs on one module conflict. `--module` prints it on demand. |
| `assets/<dotted.path>.json` | JS under `src/ux_dom`, e.g. `ux_dom.scripts.x_element.js.json`: `path`, `layer`, `referenced_by` (src modules naming the file), `consumers`. |

- **`public`**: `__all__` if defined; otherwise top-level non-underscore
  defs/classes/assignments, plus PEP 484 re-exports (`x as x`) and star-import
  expansions.
- **`imports_internal` / `imported_by`**: split into `module_level` (runs at
  import time), `function_level` (deferred: inside a function, or in an
  `if __name__ == "__main__"` block) and `type_checking` (only the body of
  `if TYPE_CHECKING:` / `if typing.TYPE_CHECKING:`; its `else:` branch and
  `if not TYPE_CHECKING:` run at import). Implicit parent-package imports are
  not edges.
- **`consumers`**: sorted repo-relative paths of **tracked** files (per
  `git ls-files`) under `tests/`, `docs/` (`.md` only), `examples/`,
  `standalone/` that use the module. `git add` a new file before regenerating;
  untracked scratch files never count. This page and `test_codemap.py` are
  excluded. This is a cheap regex heuristic:
  - a dotted `ux_dom.a.b.c` token resolves to its longest known module prefix,
    so a `monkeypatch` target counts;
  - `from ux_dom.a import b` counts `ux_dom.a.b` when that is a module;
  - a symbol reached through a re-export (`from ux_dom import Htmx`,
    `ux_dom.dom.div`) also counts for the module that defines it, using the
    same resolution as `public_api`;
  - a path `ux_dom/a/b.py` counts;
  - the bare root `ux_dom` counts only via `import ux_dom` / `from ux_dom import`;
  - an asset counts when its file name appears.

  False positives (prose mentions) are accepted.

## Guards

[`tests/04_production/test_codemap.py`](../../tests/04_production/test_codemap.py)
asserts that:

- the committed shards are fresh, and identical under different hash seeds;
- `--write-changed` rewrites only stale shards, and both write modes remove orphans;
- no module-level cycle exists beyond the allowlisted `dom_tag` ↔ `dom_util`
  (ledger E4, [#59](https://github.com/bitplorer/ux-dom/issues/59));
- the `dom` layer imports only `dom` and `support` modules, at module or
  function level (ledger E9). This is an allowlist, and any exceptions are named
  in the test;
- shards carry no `loc`;
- consumers follow re-exports;
- every module has a layer;
- untracked files are ignored;
- only the `if TYPE_CHECKING:` body counts as type-only.
