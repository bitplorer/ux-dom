# Code map — `codemap/`

[`codemap/`](codemap/index.json) is a persisted, machine-readable map of
`src/ux_dom`, sharded one file per module. It records the architecture
(layers, allowed layer edges, cycles), the codebase (modules, symbols,
imports), features, the public API, entry points and external usage, so a
refactor can start from precise context. It is generated by
[`scripts/codemap.py`](../../scripts/codemap.py) (stdlib only, AST-based) and
checked in CI. The prose companions are [ARCHITECTURE.md](ARCHITECTURE.md),
[SYSTEM.md](SYSTEM.md) and [MODULE_MAP.md](MODULE_MAP.md).

The generator is **identical in every ux-* / cek repo** that vendors it. All
repo specifics live in `[tool.codemap]` (see [Config](#config)), and
`index.json` records the generator's `version` and `sha256`, so a byte-identical
copy can be verified across repos.

## Rule

**A PR updates the map in the same change as the code. It regenerates only
the shards its change touches, and the codemap diff in review is the blast
radius:** which modules' symbols, imports, reverse edges, public names,
consumers and features moved.

### PR-author workflow

1. Edit code (and `features.toml` / `domain.toml` / the narrative docs when a
   feature, a domain concept or a cited path moves).
2. `git add` new files. Consumers are read from tracked files only.
3. `python scripts/codemap.py --write-changed`
4. `python scripts/codemap.py --check`, then commit the shards with the code.

```bash
python scripts/codemap.py --write-changed              # PR authors: rewrite stale shards only
python scripts/codemap.py --check                      # CI: exit 1 on stale shards or broken references
python scripts/codemap.py                              # rewrite every shard, remove orphans
python scripts/codemap.py --module ux_dom.cli.doctor   # one module's entry (+ loc)
python scripts/codemap.py --module ux_dom/scripts/x_element.js
python scripts/codemap.py --feature sanitizer          # one feature + its modules' summaries
```

An in-flight PR that goes stale (because `main` moved, or because it touched
`src/`, tests or docs) needs only `--write-changed`. Shards of a deleted module
are orphans: `--check` names them, and both write modes delete them.

`--check` exits 1 when a shard is stale or orphaned, **or** when the map has a
problem: a broken reference in `features.toml`, `domain.toml`, the narrative
docs or a console-script target; a layer violation; a module-level cycle not in
`allowed_cycles`; an allowlist entry (`allowed_cycles`, `layer_exceptions`,
a `depends_on` name) that no longer matches anything; or an undeclared or
private foreign import. The write modes print the same problems and exit 1, after
writing.

The output is deterministic (sorted keys and lists, no timestamps or commit
hashes), so a shard changes only when its module's symbols, imports, public
names, consumers or features change. A comment-only edit changes nothing.
There is no `loc` or line number in any shard: they change on every edit and
would make concurrent PRs on one module conflict. `--module` prints `loc` on
demand.

## Layout

| File | Content |
|------|---------|
| `index.json` | Repo-level sections, below, plus `modules` / `assets` (name → layer). |
| `modules/<dotted.name>.json` | `{name: {path, layer, doc, is_public, public, exported_as, symbols, imports_internal, imports_external, imported_by, consumers, features}}` |
| `assets/<dotted.path>.json` | Asset files matched by `assets` globs, e.g. `ux_dom.scripts.x_element.js.json`: `path`, `layer`, `referenced_by` (modules naming the file), `consumers`, `features`. |
| `claims/<dotted.doc.path>.json` | One per doc with claims, e.g. `claims/docs.guides.CLI.md.json`: `{doc: [{line, kind, text, resolved}]}`. See [Doc claims](#doc-claims). |

### `index.json`

| Key | Content |
|-----|---------|
| `schema`, `generator` | Map schema (2); generator `name`, `version`, `sha256` of `scripts/codemap.py`. |
| `packages` | Import name → package directory. |
| `layers`, `layer_rules`, `layer_exceptions` | The config, echoed. |
| `layer_graph` | Layer → other layers it imports at runtime (module or function level). |
| `layer_violations` | Runtime edges a `layer_rules` entry forbids that `layer_exceptions` does not accept. Must be empty. |
| `public_api` | Per package in `public_api.packages`: each public root name → defining module, following re-exports, star imports and `X = Y` aliases. |
| `entry_points` | `scripts` (`[project.scripts]`, `gui-scripts`, `[tool.poetry.scripts]` from `projects`), `entry_points` (`[project.entry-points.*]`), `main_modules` (`*.__main__`), `asgi` (module-level `x = FastAPI(…)` / `Starlette` / `Litestar` / `Quart`, plus config `asgi`). Internal targets are validated. |
| `cycles_module_level` | Import SCCs larger than one, module-level edges only. |
| `external_distributions` | Distribution → internal modules importing it. |
| `features` | The validated `features.toml`, by id. |
| `narrative_docs` | Docs whose citations were verified. |
| `domain` | The validated `domain.toml`: `domain`, `public_api`, `owns`, `non_goals`, `depends_on`. |
| `external_usage` | Distribution → foreign names used (`module:Name`, or a bare module when only the module object is used). |
| `coupling` | Per distribution, recorded and never failed: `import_sites`, `importing_modules`, `distinct_names`, `hard_coupling` (`isinstance` / `issubclass` against, or subclassing of, a foreign name), `port_candidates` (foreign names used in annotations and never subclassed or isinstance-checked, where a Protocol could stand in). |
| `non_goal_warnings` | Heuristic hits for `domain.toml` non-goals (warnings only). |
| `doc_claims` | `summary` (`docs`, `claims`, `unresolved`), `docs_ahead` and `code_ahead` findings (see [Doc claims](#doc-claims)). Recorded, never failed. |

### Module fields

- **`public`**: `__all__` if defined (it must be a literal list/tuple of
  strings, or the build fails with `file:line`). Otherwise, with
  `public_api.rule = "all_or_derived"`, top-level non-underscore
  defs/classes/assignments, plus PEP 484 re-exports (`x as x`) and star-import
  expansions; with `"all_only"`, nothing.
- **`is_public`**: no dotted segment starts with a single `_`.
- **`exported_as`**: `package:Name` entries of `public_api` defined here.
- **`symbols`**: top-level classes and functions (including those under
  `if`/`try`/`with`, not under `if TYPE_CHECKING:`). Each has `kind`
  (`class` / `function` / `async function`), `doc` (first docstring line),
  `decorators` when present and `public`. Functions add `signature`, e.g.
  `(self, n: int=1) -> str`. Classes add `bases` and `methods` (same shape).
- **`imports_internal` / `imported_by`**: split into `module_level` (runs at
  import time), `function_level` (deferred: inside a function, or in an
  `if __name__ == "__main__"` block) and `type_checking` (only the body of
  `if TYPE_CHECKING:` / `if typing.TYPE_CHECKING:`; its `else:` branch and
  `if not TYPE_CHECKING:` run at import). Implicit parent-package imports are
  not edges.
- **`imports_external`**: the same three kinds, each `{distribution: [modules]}`.
  `stdlib` is `sys.stdlib_module_names`; any other top-level import name maps
  through `[tool.codemap.distributions]`, else stays as the import name. No
  installed metadata is read, so the map does not depend on the environment.
- **`consumers`**: sorted repo-relative paths of **tracked** files (per
  `git ls-files`) under the `consumers` directories that use the module.
  `git add` a new file before regenerating; untracked scratch files never
  count. `self_files` are excluded. This is a cheap regex heuristic:
  - a dotted `ux_dom.a.b.c` token resolves to its longest known module prefix,
    so a `monkeypatch` target counts;
  - `from ux_dom.a import b` counts `ux_dom.a.b` when that is a module;
  - a symbol reached through a re-export (`from ux_dom import Htmx`,
    `ux_dom.dom.div`) also counts for the module that defines it, using the
    same resolution as `public_api`;
  - a path `ux_dom/a/b.py` counts;
  - a bare package root counts only via `import ux_dom` / `from ux_dom import`;
  - an asset counts when its file name appears.

  False positives (prose mentions) are accepted.
- **`features`**: ids of `features.toml` entries listing the module.

## Config

`[tool.codemap]` in the repo root's `pyproject.toml`; if that has none, the one
`*/pyproject.toml` one directory down that does (a repo with only subproject
pyprojects, like cek-python, or a project in `python/`, like ux-channel).
`--config FILE` and `--root DIR` override discovery. **All paths are relative
to the repo root.** Unknown keys fail the build. ux-dom's config is at the
end of [`pyproject.toml`](../../pyproject.toml).

| Key | Default | Meaning |
|-----|---------|---------|
| `packages` | required | Package directories, e.g. `["src/ux_dom"]`, `["ux_motion"]`, `["cek-host/src/cek_host", "cek-surface/src/cek_surface"]`. Each directory's name is the import name and its parent is the import root. |
| `out_dir` | `docs/internals/codemap` | Shard directory. |
| `assets` | `[]` | Globs for non-Python files, e.g. `src/ux_dom/**/*.js`. |
| `layers` | `{}` | Module prefix → layer. Longest prefix wins, a package name matches only its own `__init__`, and a module matching nothing fails the build. Empty means no layering (every layer `""`). |
| `layer_rules` | `{}` | Layer → other layers it may import at module or function level. Its own layer is always allowed and `TYPE_CHECKING` imports are exempt. A layer without a rule is unconstrained. |
| `layer_exceptions` | `[]` | Accepted rule-breaking edges, `"importer -> imported"`. Comment why. Stale entries fail. |
| `allowed_cycles` | `[]` | Known module-level cycles (sorted member lists). Stale entries fail. |
| `public_api.rule` | `all_or_derived` | Or `all_only`: see `public` above. |
| `public_api.packages` | all packages | Packages whose root names form `public_api`. |
| `consumers` | `{}` | Directory → file suffixes scanned for consumers. |
| `self_files` | `[]` | Files that name modules only to describe the map. |
| `features` | none | Path of the features registry. |
| `domain` | none | Path of the domain charter. |
| `narrative` | `[]` | Human-written docs whose citations are verified. |
| `projects` | the config's pyproject | pyprojects read for entry points. |
| `distributions` | `{}` | Import name → distribution name, where they differ. |
| `asgi` | `[]` | Extra `module:attr` ASGI apps (validated). |
| `claims_docs` | `[]` | Markdown files or directories whose claims are indexed. |
| `claims_exclude` | `[]` | Paths under `claims_docs` to skip (history such as ADRs or archives, which name removed code on purpose). |

ux-dom's `layer_rules` pin today's graph. `dom = ["support"]` is ledger E9
([#59](https://github.com/bitplorer/ux-dom/issues/59)), and the other rules make
any new cross-layer edge a reviewed config change. `allowed_cycles` holds the
`dom_tag` ↔ `dom_util` cycle (ledger E4).

## Features registry — [`features.toml`](features.toml)

Curated `[[feature]]` entries: `id` (kebab-case), `purpose` (one line),
`modules`, optional `assets`, `symbols` (`module:Name` or
`module:Class.method`), `tests` and `docs` (repo paths, and a test may name
`path::Class::test`). The generator validates every reference, fails on
unknown keys, and folds the entries into `index.json` and each module's
`features`. When you move or rename something a feature cites, `--check`
names the stale entry.

## Domain charter — [`domain.toml`](domain.toml)

Each library is the single source of truth for one lower-order domain and
exposes it only through its public API. Higher libraries build on that API, so
a dependency can be swapped without hard coupling. The charter makes this
checkable:

- `domain`: one sentence, naming what the library is the SSoT for.
- `public_api`: the narrow surface higher layers may use (`module` or
  `module:Name`, validated).
- `[[owns]]`: `concept`, `modules`, `symbols`, the concepts the library is the
  authority on. Every reference must resolve.
- `[[non_goals]]`: `concept`, `owner`, `keywords`. These are concepts the
  library must not own (AGENTS.md layer table). **Heuristic, warning only:** a
  module whose last name segment, or a top-level symbol whose name, contains a
  keyword as a whole word (CamelCase and snake_case are split, case-insensitive)
  is listed in `non_goal_warnings`.
- `[[depends_on]]`: `distribution`, `imports`, `names`, the lower libraries the
  library may use and exactly which of their names (`module:Name`, a bare
  `module`, or `module:*` for a whole module).
- `[law]` (optional): `url`, `concepts`, an external spec the library
  implements (for example cek-framework) and the concept ids it covers. It is
  validated for shape and recorded in `index.json` under `domain.law`, so a
  later pass can check conformance. The generator does not fetch it.

Checks that fail `--check`:

- **Undeclared dependency.** A foreign distribution (not stdlib) is used but
  has no `depends_on` entry.
- **Undeclared name.** A foreign name is used but is not listed in its
  distribution's `names`. New coupling is therefore a conscious charter edit.
- **Declared but unused.** A listed name is no longer used.
- **Private import.** A foreign module path has a `_`-prefixed segment, or a
  `src` / `internal` / `internals` / `impl` segment, or the imported name is
  `_`-prefixed.

Usage is collected from `import` / `from … import` statements (all three
kinds), plus attribute access on an imported module (`jinja2.x` records
`jinja2:x`). Whether a higher library uses only the lower library's declared
`public_api`, and whether each concept is owned exactly once across all
libraries, is checked by the ux-compose ecosystem map, which reads every
repo's `index.json`.

## Narrative check

The docs in `narrative` stay human-written, but every backticked citation that
starts with a package name must still exist. That covers a dotted module
(`ux_dom.plugins.csp`), a symbol reached through a module (`ux_dom.dom.div`),
`module:symbol` (`ux_dom.settings.document:Document.use`), and a path from the
import root (`ux_dom/settings/document.py`) or from the repo root
(`src/ux_dom/…`). Fenced code blocks and other backticked text are not checked.

## Doc claims

Docs and code are both statements of intent, and neither is automatically
right. So the map lines up what the `claims_docs` say against the code. It
records findings for audit and **never fails `--check`** on them. Only the curated
files (`features.toml`, `domain.toml`, `narrative`) are hard-checked.

Claims are collected line by line, from backticked spans in prose and from
whole lines inside fenced code blocks. Each claim records its `line`, its
`kind` and whether it `resolved`:

| Kind | Recognized as | Resolves when |
|------|---------------|---------------|
| `module` | A package citation, as in the [narrative check](#narrative-check), or any dotted `pkg.a.b` token inside a code block | The module, symbol or path exists |
| `import` | `from pkg.x import A, B` inside a code block | `pkg.x:A` resolves |
| `cli` | A span or line starting with a console-script name (`uxdom doctor`, `uxdom doctor \| lint`, `uxdom add component\|ui`) | Each named subcommand is declared in code (`@app.command("x")`, a bare `@app.command()` on function `x_y` gives `x-y`, `add_parser("x")`, `add_typer(name="x")`) |
| `env` | A span that is an `UPPER_SNAKE` name, or `NAME=` / `environ["NAME"]` inside a code block | The name is a string constant in the package, or a defined name |
| `config` | `[tool.x]` | The table exists in the config or `projects` pyprojects |

Findings in `index.json`:

- **`docs_ahead`**: unresolved claims, as `doc: kind \`text\``. Each one is
  either a stale doc or a doc describing code that does not exist yet.
- **`code_ahead`**: names with no doc support, either undocumented code or docs
  that lag behind it. It covers `public_api` names and charter `public_api`
  entries that no claims doc mentions as a whole word; console scripts, and
  subcommands never named on a line with their script; and features whose own
  `docs` name none of their modules (dotted or last segment) or symbols.

Line numbers live only in the `claims/` shards, so a doc edit re-maps only that
doc's shard.

## Guards

[`tests/04_production/test_codemap.py`](../../tests/04_production/test_codemap.py)
asserts on ux-dom's own map that:

- the committed shards are fresh, and identical under different hash seeds;
- the map has no problems, and `index.json` names this generator's sha256;
- `--write-changed` rewrites only stale shards, and both write modes remove orphans;
- no module-level cycle exists beyond the allowlisted one;
- the `dom` layer imports only `dom` and `support` modules (E9);
- shards carry no `loc`;
- consumers follow re-exports;
- every module has a layer;
- untracked files are ignored;
- only the `if TYPE_CHECKING:` body counts as type-only;
- `__all__` must be literal.

[`tests/04_production/test_codemap_fixtures.py`](../../tests/04_production/test_codemap_fixtures.py)
runs a vendored copy on synthetic repos. It covers the src layout (symbols,
signatures, decorators, entry points, ASGI, assets, external split, features,
charter, `--feature`, `--module`), the flat layout, several package roots with no
root pyproject, and a project in a subdirectory. It also checks that `--check`
fails on broken feature, narrative and entry-point references, layer violations
and stale exceptions, unlisted cycles and charter breaches. Finally, it checks
that coupling metrics, doc claims (docs-ahead and code-ahead) and the charter
`law` are recorded without failing.
